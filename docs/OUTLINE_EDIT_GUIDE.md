# Outline Agent - Edit Endpoint Guide

## Overview

The `/api/v1/agents/outline/edit` endpoint allows users to refine and modify presentation outlines generated by the `/outline/generate` endpoint based on specific feedback.

---

## Endpoint Details

**URL:** `POST /api/v1/agents/outline/edit`

**Response Time Target:** <2 seconds

**Status Codes:**

- `200 OK`: Outline edited successfully
- `400 Bad Request`: Invalid input (validation errors)
- `500 Internal Server Error`: Server error during editing
- `503 Service Unavailable`: Outline Agent not initialized

---

## Request Schema

### Required Fields

| Field                  | Type                 | Description                                   |
| ---------------------- | -------------------- | --------------------------------------------- |
| `sessionId`            | string               | Session identifier (same as generation)       |
| `userId`               | string               | User identifier                               |
| `previousOutline`      | PresentationOutline  | The outline from `/outline/generate` response |
| `userFeedback`         | string               | User's edit request/feedback message          |
| `extractedInformation` | ExtractedInformation | Original presentation requirements            |
| `queryResults`         | array                | Query results from RAG (same as generation)   |

### Optional Fields

| Field                | Type                    | Description                                                           |
| -------------------- | ----------------------- | --------------------------------------------------------------------- |
| `targetSlideForEdit` | integer                 | Specific slide number (1-indexed) to edit, or `null` for global edits |
| `synthesizedContext` | SynthesizedContext      | Synthesized context from Query Agent                                  |
| `generatedQueries`   | array                   | Generated queries metadata                                            |
| `performanceMetrics` | PerformanceMetricsInput | Performance metrics from Query Agent                                  |

## User Feedback Guidelines

### Good Feedback Examples ✅

1. **Specific and actionable:**

   - "Add a bullet point about investor implications to slide 3"
   - "Change the bar chart on slide 5 to a line chart"
   - "Reduce bullet points on slide 2 from 5 to 3"

2. **Clear intent:**

   - "Make the tone more formal throughout"
   - "Emphasize the 65% volatility reduction metric"
   - "Move recommendations earlier in the presentation"

3. **Data-focused:**
   - "Add exact percentage changes to slide 4"
   - "Include volume data for the highest trading day"
   - "Fix the query reference on slide 7 to query_3"

### Vague Feedback Examples ❌

1. ~~"Make it better"~~ → Too vague
2. ~~"Fix slide 3"~~ → What needs fixing?
3. ~~"Add more stuff"~~ → What kind of content?
4. ~~"I don't like it"~~ → What specifically?

**Tip:** Be specific about what you want changed and why.

## Workflow

### Typical User Flow

1. **Generate outline:**

   ```
   POST /api/v1/agents/outline/generate
   → Get initial outline
   ```

2. **Review outline:**

   ```
   User reviews the presentationOutline in the response
   Identifies areas for improvement
   ```

3. **Request edit:**

   ```
   POST /api/v1/agents/outline/edit
   → Pass previous outline + user feedback
   → Get updated outline
   ```

4. **Iterate if needed:**

   ```
   Can call /edit multiple times
   Each time passing the most recent outline
   ```

5. **Accept and proceed:**
   ```
   When satisfied, proceed to content generation
   (handoff to Content Agent)
   ```

## Key Features

### ✅ What the Edit Endpoint Does

- **Preserves context:** Maintains narrative flow and data integrity
- **Targeted changes:** Can focus on specific slides or edit globally
- **Data validation:** Ensures all data mappings remain valid
- **Tracks changes:** Documents all modifications in `editingMetadata`
- **Quality checks:** Re-validates outline for compliance and quality
- **Maintains compliance:** Keeps 8-10 slide limit and structure

### ❌ What It Doesn't Do

- **Re-run queries:** Uses same `queryResults` from generation
- **Change requirements:** `extractedInformation` remains the same
- **Generate new data:** Only works with existing query results
- **Break structure:** Won't violate 8-10 slide constraint

## Best Practices

### For Frontend Developers

1. **Store generation response:** Keep the full `/outline/generate` response
2. **Provide clear feedback UI:** Help users write specific feedback
3. **Show diffs:** Highlight what changed in `editingMetadata.modifiedSlides`
4. **Allow iterations:** Let users edit multiple times
5. **Validate before submit:** Check `userFeedback` is not empty

### For Users

1. **Be specific:** Clear, actionable feedback gets better results
2. **Focus edits:** Use `targetSlideForEdit` for single-slide changes
3. **Iterate gradually:** Make incremental improvements
4. **Review changes:** Check `editingMetadata` to see what changed
5. **Accept when ready:** Don't over-edit; trust the initial generation

## FAQ

**Q: Can I edit an outline multiple times?**  
A: Yes! Just pass the most recent outline as `previousOutline` each time.

**Q: Do I need to provide the same queryResults as generation?**  
A: Yes, the edit uses the same data context. No new queries are run.

**Q: What if I want to change the slide count?**  
A: The agent maintains 8-10 slides. You can request restructuring, but it won't exceed limits.

**Q: Can I add completely new content not in the data?**  
A: No, all content must be backed by `queryResults`. The agent won't fabricate data.

**Q: What's the difference between targetSlideForEdit null vs specific number?**  
A: `null` = global edit affecting multiple/all slides. Specific number = focused edit on one slide.

**Q: How do I know what changed?**  
A: Check `outlineMetadata.editingMetadata` for `modifiedSlides`, `addedSlides`, etc.
